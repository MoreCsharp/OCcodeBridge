# 套餐用量

用量窗口由凭据所属**厂商**返回：插件把 `FetchUsage` 的结果转成统一的窗口列表，再同时供管理页和 CPA 配额接口使用。插件不再基于价格推算额度金额。

## 管理页

在「凭据管理」展开凭据可看到厂商返回的窗口：套餐名称、当前周期、已用百分比和重置时间。时间按浏览器本地时区显示，百分比使用厂商返回值；缺失值显示 `—`，不当作零用量。

凭据按名称排序，每页 12 个，可搜索名称或 ID。支持单个刷新和刷新本页。插件后台按凭据约每分钟查询用量，不依赖页面、分页或浏览器是否打开。最多同时查询 3 个凭据，常规结果缓存 60 秒，手动刷新保留 10 秒最小间隔；后台遇到鉴权失败或限流时退避 5 分钟。凭据较多或上游变慢时采样间隔可能延长。

查询失败保留上次成功数据并显示时间、过期状态和原因；首次失败显示未知，不显示为 0%。更换 API Key 或厂商后旧缓存失效，旧请求的结果也不会覆盖新 Key。手动停用和额度暂停不阻止用量查询，查询保留人工启停状态。用量查询不会参与模型推理或凭据轮转。

窗口种类由厂商给出，插件只认四种：

| 厂商窗口 | CPA 配额窗口 | 管理页标签 |
| --- | --- | --- |
| `5h` | `5h` | 5 小时 |
| `7d` | `7d` | 每周 |
| `daily` | `daily` | 每天 |
| `month` | `monthly` | 每月 |

未识别的窗口种类会被忽略，不会猜成其他档位。

## CPA 标准配额接口

插件通过 CPA JSON ABI 声明 `quota_provider` 能力，并提供 `quota.identifier`、`quota.describe`、`quota.fetch` 和 `quota.reset`。CPA 据此在插件及凭据列表中生成 `supports_quota: true` 和 `quota_provider: "planbridge"`。

外部管理客户端可以调用 `POST /v8/management/plugins/planbridge/quota`，请求体为 `{"auth_index":"<auth_index>"}`。`auth_index` 取自 CPA 凭据列表，由 CPA 解析到对应账号；插件不会回退到其他账号。相应 GET 路由支持 `?auth_index=<auth_index>`。

响应使用 CPA 标准的 `subscription` 和 `groups[].buckets[]`：厂商窗口按上表映射，`remainingFraction` 为 0–1 的剩余比例，`resetTime` 使用厂商重置时间。缺失百分比的窗口不生成额度条，不推断为零用量或额度耗尽。标准接口只输出厂商显示名称和已报告窗口，不输出 API Key、账号标识或任何估算金额。

标准接口复用页面及后台采样的缓存、查询合并、代理和额度保护逻辑，主动查询保留 10 秒最小间隔。手动停用及额度暂停的账号仍可查询。上游查询失败时标准接口返回错误，避免把旧数据作为当前配额；插件自身页面仍保留旧值和过期提示。

上游不提供额度重置操作，`quota.describe` 声明 `supports_reset: false`，`quota.reset` 返回 `success: false`，不清除 CPA 冷却、不修改账号启停状态或额度保护。

## 接口与兼容性

- 插件管理接口：`GET /v0/management/planbridge/credentials/usage?id=<凭据ID>`，手动刷新可加 `refresh=1`，由 CPA 管理鉴权保护。
- 厂商来源：由各厂商子包的 `FetchUsage` 决定。`opencode-go` 与 `commandcode` 目前返回 `ErrNotImplemented`，页面会显示该凭据的用量暂不可用。
- 请求凭据没有厂商时，用量查询直接返回不可用并提示选择厂商，不会访问任何上游。
- 上游鉴权失败、限流、超时等以该凭据的查询状态返回，不会误触发 CPA 管理密钥登录弹窗。
- 代理池关闭且凭据未指定独立代理时，用量查询使用 CPA 的宿主 HTTP 回调和全局代理。启用代理池或凭据配置了 `proxy_url` 时，查询通过插件传输，独立代理优先；代理连接失败会显示查询错误，不会绕过指定代理直连。查询也计入相应出口组的请求和并发预算。

## 测试包

普通分支推送只触发 GitHub Actions 构建。可以在对应提交的 workflow run 中下载 `package-linux-amd64` 等平台产物进行测试；正式市场安装仍取已有 Release。测试阶段不创建版本 tag 或 Release。

建议验收：检查厂商实际返回的窗口；添加多凭据后检查搜索、翻页和单独刷新；编辑 Key 或切换厂商后确认数据随之更新；切换 CPA 明暗主题和窄屏检查布局。
